## 0. Target payment state machine (build this first in your head)

Today `confirmPayment` jumps `execute → confirmed` from the **browser handler**. That is the root bug.

```text
window ──► execute
              │
              ▼
     create Order (Razorpay)     [MUST succeed or fail-closed]
              │
              ▼
     open Checkout WITH order_id  OR  token charge
              │
              ▼
           pending                 [handler only means "user finished UI"]
              │
      ┌───────┴────────┐
      ▼                ▼
   webhook          poll Fetch
 payment.captured   GET /payments/:id
      │                │
      └───────┬────────┘
              ▼
     verify signature
     idempotent apply
              ▼
          confirmed                [ONLY here: remainingPaise -=, stock -=]
```

Add on `PurchaseAttempt`:

```ts
razorpaySignature: string | null
razorpayStatus: "none" | "created" | "pending" | "captured" | "failed" | "unknown"
confirmSource: "none" | "handler_unverified" | "fetch" | "webhook"
attemptsCharge: number          // retry count
```

Never decrement mandate in the Checkout `handler`. Handler only stores ids and sets `pending`.

## P0-2. Orders API is the only live execute path

**Why.** Track: *using Razorpay test-mode APIs*. An order is the durable object webhooks attach to.

**Now.** `openLiveCheckout()` calls `createRazorpayOrder`; without secret `orderId` is `null` and Checkout runs on amount only ([`checkout.ts`](src/lib/safebuy/checkout.ts) `order_id: opts.orderId || undefined`).

**Pipeline**

```
startExecute (after notify window)
  → POST /v1/orders
       amount = cart.totalPaise
       currency = INR
       receipt = attempt.id.slice(0,40)
       notes = { correlationId, mandateId, attemptId, merchantId }
       payment_capture = 1
  → persist attempt.razorpayOrderId
  → audit event razorpay.order_created layer=live
  → ONLY THEN open Checkout { key, order_id, amount, handler }
```

**Rules**

- No `order_id` → **do not** open Checkout. `failClosed("order_create_failed")`.

- Put `Idempotency-Key: attempt.id` header on Orders (P1-5). If Razorpay ignores it, still dedupe locally: same `attempt.id` must not create a second order.

**Parts**

| Part | Job |
|------|-----|
| Orchestrator `startExecute` | Gate: window elapsed, guardrail already passed |
| `createRazorpayOrder` | HTTP Basic `key_id:key_secret` |
| `openRazorpayCheckout` | `order_id` **required** |
| Audit | `orderId`, `amount`, `receipt` |

**Done when.** Dashboard → Orders shows the order **before** you type the test card.

## P0-3. Wire `fetchRazorpayPayment` as source of truth for “captured”

**Why.** Function exists and is **dead**. `confirmPayment` trusts the client. Spec: webhook **or poll**; sync response is not final.

**Now.** [`store.ts`](src/lib/safebuy/store.ts) `confirmPayment` immediately subtracts `remainingPaise`.

**Pipeline**

```
Checkout handler(payment_id, order_id, signature)
  → audit razorpay.handler_received  (NOT confirmed)
  → attempt.phase = pending
  → attempt.razorpayPaymentId = payment_id
  → startReconcile(attemptId)

startReconcile:
  loop i in 0..N (N=6, delay 2s — disclose as demo, not UPI SLA)
    GET /v1/payments/:payment_id     already sketched in fetchRazorpayPayment
    optionally GET /v1/orders/:order_id
    if status in {captured, authorized}:
         applyConfirm(source="fetch")
         return
    if status in {failed, cancelled, refunded}:
         failClosed
         return
  timeout → failClosed("poll_timeout")
            leave a flag reconcileOnWebhook=true
```

**`applyConfirm` (single function, used by fetch AND webhook)**

Preconditions:

- attempt exists  
- not already `confirmed`  
- `payment.amount === cart.totalPaise`  
- `payment.order_id === attempt.razorpayOrderId`  
- signature valid if present  

Then:

- mandate.remainingPaise -= total (once)  
- stock decrement (P1-6)  
- phase `confirmed`  
- audit `razorpay.confirmed` with `source`, `status`, `paymentId`

**Soft-decline lab** must call the **same** `startReconcile` with a stub status `failed`, not the current shortcut at `store.ts` ~443.

**Done when.** Network tab shows GET payment after handler; mandate number changes only after `captured`.

## P0-4. Webhook + HMAC + tunnel

**Why.** Spec: webhook is source of truth; poll is fallback. Sandbox cannot receive Razorpay; **your laptop can** via tunnel.

**New pieces**

```
src/routes/api/razorpay/webhook.ts     POST raw body
src/lib/safebuy/razorpay-webhook.ts    verify + map event → applyConfirm / failClosed
```

**Pipeline**

```
Razorpay
  → POST https://<tunnel>/api/razorpay/webhook
  headers: X-Razorpay-Signature
  body: { event, payload.payment.entity | payload.order.entity }

Your server:
  1. Read RAW body string (not re-serialized JSON)
  2. expected = HMAC_SHA256(raw, RAZORPAY_WEBHOOK_SECRET) hex
  3. timingSafeEqual(expected, header) else 400
  4. switch event:
       payment.captured / order.paid → applyConfirm(source="webhook")
       payment.failed                → failClosed if not already confirmed
  5. Always 200 after durable persist (or 200 + ignore duplicate)
```

**Dashboard**

- URL: tunnel HTTPS  
- Events: `payment.captured`, `payment.failed`, `order.paid`  
- Secret → env  

**Race with poll**

```
applyConfirm is idempotent on payment_id
if already confirmed: audit razorpay.duplicate_ignored, return
```

**Local runbook (README)**

1. Start app.  
2. Tunnel `https://xxx` → app `/api/razorpay/webhook`.  
3. Paste URL in Razorpay test webhooks.  
4. Do one payment.  
5. Audit must show `source=webhook` **or** `source=fetch` then duplicate ignored.

**Done when.** You can close the tab after handler and still land `confirmed` from webhook **or** poll.

## P0-5. Checkout handler signature verification

**Why.** `RazorpaySuccess` has `razorpay_signature` unused. Anyone can call `confirmPayment` from the client today.

**Pipeline**

```
handler payload:
  razorpay_order_id
  razorpay_payment_id
  razorpay_signature

server verifyCheckoutSignature({ orderId, paymentId, signature }):
  message = `${orderId}|${paymentId}`
  digest  = HMAC_SHA256(message, RAZORPAY_KEY_SECRET) hex
  timingSafeEqual(digest, signature)
```

If invalid → `failClosed("bad_signature")`, do not poll as success.

Call this **before** `startReconcile`. Webhook uses **webhook secret** (different key). Do not mix them.

**Done when.** Tampering `payment_id` in DevTools cannot confirm.

## P1-1. Soft decline: fetch, then at most one retry

**Now.** Lab inject never hits Razorpay; chat lies “Fetched status first.”

**Pipeline**

```
execute → Order created
       → Checkout / charge
       → pending
       → Fetch status = failed | (lab: inject failed)
audit payment.soft_decline { paymentId, status, retry=0 }

IF retryCount == 0 AND status === failed AND order still payable:
  retryCount++
  create NEW order OR reuse if dashboard allows
  open Checkout again
  pending
  Fetch again
IF still failed:
  stop, notify user, no third charge
```

**Invariant.** Never fire a second Order without a Fetch saying the first is `failed` (not `created`/`authorized`).

**Done when.** Lab “soft decline” goes through `fetchRazorpayPayment` (mockable), audit has two Fetch rows, mandate unchanged.
